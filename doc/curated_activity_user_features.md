# Life｜活動探索產品規格（2026-10-16）

**現行唯一活動 UX 規格；以 GitHub main implementation、CI、staging、production／runtime 實證判定完成狀態。** 本版取代 2026-10-11 的「限時機會／活動探索」雙導覽規劃，保留後端兩種查詢語意和舊資料相容性，不代表新版本已部署。

## 產品入口與資料唯一性

- 使用者功能只顯示 **「活動探索」一個導覽入口及一張首頁卡片**。進入後僅保留「全部活動」主列表與「已收藏」個人篩選；**移除「限時機會」獨立切換按鈕**。限額優惠、即將開報、報名截止等仍全部在「全部活動」中呈現，不另設第二個列表或資料庫。
- 上游仍為 ChatGPT 探索／核證 → Drive 精選池 → 獨立交接 Sheet → Life 每日 GCP Job → PostgreSQL curated pool。不新增 Life crawler、模型或另一套收藏 DB；維持 `event_key/content_hash` 去重、版本回執及原有資料。
- 後端暫保留 `entry=explore` 與 `entry=opportunities` 作舊客戶端相容，但使用者統一以 `entry=explore` 查詢全部活動（包含報名、預約、開放領取、優惠與截止等需要採取行動的候選）。**一筆活動可以被兩個視角找到，但同一次畫面列表只能有一張主活動卡片**；不同優惠／日期／場次折入同一主活動卡片，保有子項來源與差異。分頁之間亦必須避免同主活動重複；不得因移除限時切換而在全部活動漏列原限時機會。
- 以穩定 `parent_event_key`／`handoff_event_key` 歸併主活動，`identity_key` 保留子項與既有個人紀錄映射。不得僅依標題相似就誤合併不同活動；去重必須涵蓋匯入、後端查詢、前端分組、個人操作。
- 舊 `/more/opportunities`、`/more/curated`、`/more/events` 等外部入口與既有偏好保留相容／導向；使用者新導覽和新首頁只有活動探索，個人 `pinned`／`more_order`／`home_cards` 中的 `events`／`opportunities` 對應到同一 `explore` 入口並去重；**不得自行刪掉舊私人收藏／待辦／日曆標記**。
- 管理員原有 `explore`／`opportunities` rollout 旗標先保留，活動探索視角受 explore 控制、限時視角受 opportunities 控制；舊 URL 仍檢查對應權限。合併導覽並不是繞過功能權限。

## 列表與篩選

- 查詢 **整個 PostgreSQL 範圍**，首頁第一批只顯示 **5 個主活動群組**，按「再看 10 筆」續取 10 群組；不在 Flutter 先載完整資料。使用穩定排序、正確 `has_more/next_cursor` 和一致版本游標，避免換頁漏項或重複。
- 全部活動預設兼顧正在進行、接近開始與即將截止／開報的時效；已收藏可回查失效／結束資料並標註。**活動開始日不得冒充報名截止或開放日**，未知不補造。
- 「全部活動」速查：最新收錄、正在進行、本週末；「更多」內提供7天內、30天內、免費活動、即將開報、今天開報、3天內截止、限額優惠及時間待公布。已收藏作為同一列表的個人篩選。查詢互切需重置分頁並正確回讀。
- 一般搜尋欄查標題、主辦單位、現有地點（縣市／行政區／場地）、`summary`／現有可用摘要；中文包含比對且在 DB 全量搜尋。摘要可能只是 `evidence_summary`，不得寫成官方全文。更多篩選僅含地區、動態類別、日期、可靠費用分類、個人收藏；未知與資訊待核應明示。
- 預設不顯示上游 1／3／5 星，也不用星等排序或篩選。外部網址及「免費」「已可報」「尚有名額」必須有相應證據；活動資料以來源原頁為準，不製造自動報名保證。

## 卡片與個人操作

- 卡片顯示主標題、合適的日期／限時資訊、地區／地點、已知費用與必要資格、核證狀態；預設簡潔，詳細內容及子項可展開。
- **只保留三項使用者動作：收藏、建立待辦、日曆日期標記**。收藏應以主活動唯一身份對應且跨兩個視角同步；歷史子項收藏／操作保留可回查，不因 UI 合併而重複或遺失；依 Google `sub` 隔離使用者資料。
- 「建立待辦」沿用既有 Task（標題、備註、`source_type/source_ref`），到期日可選／調整，不自動填猜測的截止日；連結是對應活動／子優惠的可信網址。在 Life 待辦清單上可點「前往網址」。
- 「日曆日期標記」沿用既有 Google Calendar：有據日期、全天事件、end.date exclusive、`transparency=transparent`、無預設提醒、不暗示已報名；正確來源網址寫入 description，Life 日曆詳情提供可點「前往網址」。未知日期時拒絕建立，不自動寫今日。
- 同一帳號、主活動與同場次／同日期的重試需 idempotent。私人待辦／Calendar 已由使用者編輯時，不因來源重新匯入而靜默覆寫或刪除。外部網址限經驗證的 HTTP(S)，不能開任意 URI scheme。
- 本期不新增個人推播、代報名、外部報名席次驗證、GPS、旅遊行程自動化或 AI 搜尋。

## UI 整合與驗收

- 全部業務 UI 沿用 Material 3 五風格、響應式版型。活動功能入口只展示一次；首頁不再為相同精選活動／限時機會內容堆疊重複卡片。個人首頁舊選擇值載入時去重；後端相容值暫留。
- 驗收必須涵蓋：主子項分組與跨分頁去重、欄位缺值、Google `sub` 隔離、收藏／待辦／日曆舊資料、搜尋／期限／跨日、舊 URL、權限切換、行動／桌面顯示、可靠網址。
- 以 **implementation／tests／CI／staging／production／runtime／integration** 分別回報 `PASS / FAIL / NOT VERIFIED`；完整證據前只可標 **PARTIAL**。上游交接規格唯一來源：[curated_sheet_job_ingestion](curated_sheet_job_ingestion.md)，不變更本次探索排程或 Sheet。


## 2026-10-18｜活動卡片去除稽核資訊、統一所有來源連結
- BeClass、EventGo（eventgo.tw）、ACCUPASS、KKTIX、小藝與其他公開主辦／活動來源，不依平台建立特別流程。保留 `source_url` 發現網址、`official_url` 主辦活動頁（未取得時可暫存平台具名活動原頁並明確標待核）、`registration_url` 報名表；前台顯示來源網域或平台標籤及可點的來源連結，報名按鈕仍開獨立報名 URL。
- 未來有具名主辦官網時同一 `event_key`／`parent_event_key` 更新 `official_url`、核證狀態及內容版本，維持 `source_url`、`registration_url`、使用者收藏、待辦、日曆既有對應；不能因來源補核而新增重複活動。
- 手機卡片不再顯示原始 `summary/evidence_summary` 的精選池、可信度、批次、索引或其他系統文字；預設只顯示活動名稱、易讀日期、地區、核證狀態、費用。詳情預設收合，列有據的主辦、地點、日期、報名條件、來源連結和既有個人操作。
- 本輪僅修改 GitHub 原始碼、測試程式碼及規格，依使用者指示停在修改階段：tests/CI/deploy/runtime 均 NOT VERIFIED，合併另一塊改動後再驗收。

## 2026-10-22｜移除限時機會獨立視角
- 使用者確認移除活動探索畫面中的「限時機會」切換，所有一般活動與限時機會統一由「全部活動」呈現；「已收藏」保留個人篩選。
- 既有 `opportunities` 後端查詢、舊路由、收藏與個人設定僅為相容用途，不得直接刪除導致舊連結或個人資料失效。
- 驗收需核對舊限時機會在全部活動完整可見、同鍵去重、截止/開報資訊正確、行動裝置篩選與收藏不退化。本文為產品規格；未有程式、CI 與實機證據前不得宣稱已發布。
