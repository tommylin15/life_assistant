# 精選池使用者功能 — 正式產品規格（2026-10-10）

**狀態：DESIGN APPROVED / IMPLEMENTATION NOT VERIFIED。** 本文件是「精選池資料進入 Life 之後」唯一正式使用者功能規格；當前 API / Flutter 已有**共用精選池基本瀏覽**，但下述兩入口、個人動作、預警和旅遊候選**尚未因此視為已實作**。實作狀態看 [CURRENT_STATE](CURRENT_STATE.md)、GitHub main 和真實 runtime。

## 邊界與共用資料

唯一資料入口：**ChatGPT 自行探索及精選 → Life 已授權批次 API → 單一 PostgreSQL curated pool → 使用者 UI**。Life 不做官網/Excel/文化部/TDX 掃描、Source Job、Queue/ACK、第二輪 AI 推薦或發布審核。入口契約請看 [現行活動管線](taiwan_free_events_discovery_plan.md) 和 [現有 API 契約](free_events_candidate_ingestion_contract.md)；本文件不重複維護輸入 schema。

**共用一筆資料，不拆成兩個資料來源。** 同一活動可包含一般活動、限量場次或優惠，允許同時出現在兩個功能；可在後續版本設計母活動／子場次（相同原始 URL 可用既有 occurrence_key 區別），避免在清單間複製相同實體。精選不代表已核實可報名、尚有名額或保證優惠。

## 兩個獨立使用者功能入口

| 入口 | 主要目的 | 核心資訊 | 核心動作 | 行事曆預設語意 |
|---|---|---|---|---|
| **限時機會** | 不錯過可行動的機會；報名、預約、限量／限時優惠、名額、領券 | 開放時間、截止、條件、報名狀態、名額／庫存及證據（未知須顯示未知） | 追蹤、提醒、加入待辦；完成後可加入確定行程 | 行動時間點（開放、截止），與實際參與日分開 |
| **活動探索** | 發掘值得參加的活動與旅遊規劃中繼站 | 開始／結束日期、地點、內容、交通／來源（有資料才顯示） | 收藏、標記活動日期、加入未來旅遊候選 | 活動期間的資訊標記，不等於占用個人時間 |

使用者可由同一活動卡進入兩者，不得為互斥分類而遺失其報名機會。名額耗盡、取消、延期、報名窗口未知等情況需明確表達；未經來源證據不得自行推測精確時間或可用名額。

### 評級、時效與用途分離

**1–5 星價值**、需不需要動作、時間急迫性、是否適合旅遊、活動類別，彼此是獨立維度；不能把「五星＝要搶名額」或「一般活動＝低星」寫死。現有 curated schema 有 `importance`、`registration_required`、`registration_status`、`limited_offer`、`registration_deadline`，但尚缺獨立的使用者追蹤／提醒語意和開放時間等欄位。新增欄位前另做 additive migration 和契約驗證。

## 使用者自主動作（不因瀏覽自動建立）

從精選池卡片提供簡潔的「收藏／追蹤」「加入」入口，展開後可**分別勾選**：
- **追蹤提醒**：尤其是限時機會的報名開放／截止，可選提前預警；沒有可信開放時間，不排程假精確提醒，只允許不含捏造時間的追蹤／待確認。
- **建立待辦**：例如「10/14 開放後報名」。僅用於需要個人行動的事項；一般活動探索預設不建待辦。
- **加入行事曆**：選擇「活動日期標記」「報名／截止提醒」「確定參與行程」之一；活動範圍標記不得每日占滿 busy 時段。日期範圍未知時不建立假日程。
- **加入旅遊行程候選**：未來旅遊規劃功能的輸入；本期只保留契約／擴充點，不能假稱旅遊行程編排已完成。

預設四項均由使用者自行決定，不因精選入池、瀏覽、收藏、啟用功能或後台開關，自動寫入個人 Tasks／Google Calendar／通知訂閱。勾選和取消分開控制，同一來源重試不得重複建立個人項目；可由使用者決定保留、更新或刪除已有個人副本，且修改共用精選池時不能靜默覆寫已確認私人行程。

## 行事曆與通知語意

- **報名提醒**：有明確、含時區的開放／截止時間時，才可選提前一天、一小時或個人化間隔；提醒本身不代表已報名。
- **活動日期標記**：是資訊參考，可為全天日期或日期區間，不代表使用者確認參加、不得自動設為忙碌或創造一整個月的占用。
- **確定參與行程**：使用者明確確認後，使用其選定的實際日期／時段，可呈現在個人行事曆。
- **通知**：以偏好、政策、來源時間可信度與時區決定；失效／截止停止不當催促。Google Calendar 寫入需要每位使用者自己的 OAuth 與明確授權。Google API 失敗不可回報成功；重試需 idempotency。

限時機會可由使用者自行管理「想報名 → 等開放 → 已送出／待確認 → 成功／候補／失敗／取消」，但**狀態是使用者追蹤資訊，不是官方票務驗證**。未來報名成功後可加入旅遊行程；不得在 Life 內自動代報名、代搶票、支付或繞過名額限制。

## 產品導覽、個人與後台權限

- 手機沿用 Material 3 底部導覽，桌面使用左側 Rail／Sidebar；**兩個入口獨立受後台 feature rollout 控制**。使用者可在可用功能範圍內調整排序、釘選及首頁摘要卡片。
- 後台只可控制功能開放與全站精選池資料／操作錯誤，不能代用戶操作私人待辦、行事曆、通知或讀取其 Google 授權內容。
- 精選池公共資料與使用者個人追蹤、收藏、待辦、行事曆／旅遊候選完全隔離，依 `user_sub` 授權；寫入必須有權限、去重、audit，不能跨帳號顯示。
- Life 管理的 Drive AI Provider 與 ChatGPT 獨立探索、Google Drive 優惠研究工作完全分離。本次**不改 Drive 工作流**。
