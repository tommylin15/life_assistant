# Gmail 智慧事項雷達 — V1「單人手動快掃」

日期：2026-10-16（Asia/Taipei）
**最新核准範圍：僅手動個人快掃；每小時排程、全員掃描、主動推播全部暫緩。**
文件類型：核准需求／工程設計；實作、CI、staging、正式版、真實帳號整合均須個別證據才能標 PASS。

## 產品定位
Life 不複製 Gmail 全信箱，不做郵件用戶端。使用者在 Life「Gmail 智慧事項雷達」按「立即快掃」後，僅讀目前登入者所連結且有效授權的 Gmail 近期候選郵件，辨識有生活行動價值的資訊，寫入本人的「Gmail 事項清單」，附上原信連結。使用者可以忽略或完成事項，完整內容回 Gmail 查閱。
此功能與使用者輸入自由文字的「生活收件匣」是不同入口，不新增另一套 Task 或 Calendar。未經本人明確按下轉換動作，不代替使用者建立待辦或日曆。

## V1 UI
- 獨立功能頁與個人化可選導覽。右上角明顯「立即快掃」按鈕，旁邊只顯示上次真實掃描時間／此次掃描結果，**不顯示尚未實作的排程開關**。
- 有 Gmail OAuth 授權才允許開始。缺少授權顯示「前往個人化 → Google 服務連結」。
- 扫描中禁止本裝置重複點擊；後端確保登入者專用 scan 狀態互斥（多瀏覽器），掃描結果：已檢查／新增事項／已存在略過／失敗數／時間。零筆新發現仍是成功；錯誤不得顯示掃描成功。
- 事項卡：分類、簡短標題／摘要、來源寄件者與日期（有證據才顯示）、原始 Gmail 連結、待處理／已完成／已忽略。盡量少保存敏感資訊。
- 先實作「原信查看、完成、忽略」；後續沿用既有手動 Gmail→Task/Calendar 操作（需個人確認），不另外做自動寫入。

## 2026-10-17｜Gmail 快掃、補檢與輕量收件匣整合（較舊 V1 數字以此節為準）

- **卡片只保留主要動作**：待處理顯示「送到生活收件匣」與「開啟 Gmail 原信」；有成功儲存回執後改顯示「開啟已儲存功能」和「開啟 Gmail 原信」。Gmail 信箱備援及手動完成／忽略／恢復移到「⋯ 更多」。備援是開啟所有郵件而非備份；原信路由不能保證手機／多帳號一定直達。
- **手動快掃**：最近 7 天最新 20 封；額外分頁列出最近 3 天的 ID（最多 2,000 個），提供已列出封數、本輪檢查、新事項、尚待補檢、失敗數。超過上限只能顯示已列出至少數，不得假報全部掃完。
- **三天補檢**：使用者自行按，一次最多補查 40 封尚未查過的 ID；可重按以處理剩餘，掃描進行時防止同人併發，不設一小時冷卻。掃過含規則未命中的信僅記錄 owner+message ID 去重；不保存正文、不呼叫 Gemini。
- **送到生活收件匣**：只帶入該封標題、snippet、原信 URL，使用者仍須明確按「智慧辨識」（這一步可能使用 Gemini）並親自確認儲存。後端核對本人 inbox.create 成功回執，才能把 Gmail 項目標示完成、保存目標類型與 ID；單純開啟頁面／智慧分類／UNKNOWN 不標完成，不建立第二套 Inbox。
- **功能連結限制**：目前連至待辦／筆記等功能入口，未保證直接開啟某一筆 item；各功能 ID deep link 需要獨立 UI/驗收，不造假。
- 不加入 Scheduler／推播／自動 AI。工程、四 CI、Staging 與 Gmail/目標 DB 真實讀回分別驗證，統一在 doc/todo.md P1-G1 追蹤。

## 2026-10-17｜手動雷達擴充：帳號風險、費用及待辦通知

- 保留原本 5 類（繳費、取貨、預約、航班、期限）；新增 4 個明確類別：`security`（帳號異常登入、非本人交易、密碼／雙重驗證變更及疑似盜刷）、`account`（付款失敗、扣款／續訂費用警示、帳號停權風險、儲存空間將用完）、`refund`（退款失敗／遭拒／延遲、訂單取消／支付異常／需要回覆）、`administrative`（政府補件、學校待回覆／同意書、工作簽核／文件期限）。
- **廣告先排除**：標題有促銷、優惠、折扣碼、電子報等明確商業文案即不列提醒。主旨能明確表示異常／應處理事件時優先採信主旨，不因頁尾「取消訂閱」誤排除；主旨模糊、只有摘要有警告詞時，若摘要出現促銷內容則拒絕升級提醒。
- **一般正常通知不升級成風險**：純驗證碼、普通新登入成功、退款成功、訂單成立、政府新聞、學校公告等不因此建立待辦。不能宣稱已完整防漏：語言、寫法、轉寄或模糊措辭均可能漏檢／誤判。
- 這是 **metadata subject/snippet 的規則初篩**，不是 Gmail 寄件者身份／SPF、DKIM、DMARC 真偽認證，更不代表銀行扣款或安全事件已被 Life 證實。UI 明確提醒使用者透過官方 App 或自行輸入網址查證，不引導點擊信內付款／登入連結。
- **仍只在按下「立即快掃」或「三天補檢」時辨識**，無 Gemini、無排程、無推播。所有已成功掃描的郵件 ID 會去重；**新版規則不會自動重新檢查此前已掃描並略過的郵件**。新郵件／首次掃到的尚未查郵件適用新版；不要冒充歷史已全數回填。
- 不變更 Gmail OAuth scope、不存正文／附件、不另建通知功能與 AI 模型成本。規則誤判回歸測試、四項 CI、固定 Staging、真人 Gmail 帳號 readback 分層驗收，唯一工項仍為 `doc/todo.md` P1-G1。

## 2026-10-17｜補正已掃過與授權通知（P1-G1，不另建系統）

- **Gmail 已讀不影響 Life**：Gmail 和其他應用程式的已讀／掃描紀錄不是 Life 來源篩選條件。影響快掃重複判讀的是 Life 自己的 `(user_sub, gmail_message_id)` 去重紀錄；原本被規則排除的信會保持已查狀態。
- **新增「重新檢查近三天」手動按鈕**：每次以最新 40 封為上限，包括 Life 以前已檢查但當時未命中的郵件；不修改或刪除 `gmail_radar_seen` 既有鍵、已完成／忽略的 `gmail_radar_items`、Life Inbox 成功回執。新命中的提醒新增一次，不會清空或覆寫。
- **正常授權與值得確認分開**：Google 驗證碼、一般成功登入、自己剛完成的 OAuth 授權及廣告不直接標示有風險；第三方 App 新取得帳號存取權、授權範圍／應用權限變更可列 `authorization`「第三方應用程式授權／權限變更」供自行至官網查證。只比對 Subject／Snippet，非身份真偽驗證；沒有命中不等於沒有風險。
- 與既有「三天補檢」差異：補檢只補 40 封**尚未檢查**的 ID；重新判讀則允許重新檢查最新 40 封**已檢查**的 ID，兩者不可混稱。掃描狀態顯示 `recheck`；不得以 `added=0` 偽稱 Gmail 空信箱。維持手動、無排程、無 AI、無推播。當次錯誤不可將上次掃描的成功計數冒充本次完成。
- 驗收：分類正／反案例、Life 去重＋重判、Flutter 按鈕、四 CI、固定 Staging 發布、真人 Gmail 最新三天 38 封可見／實際授權郵件能否命中、不同帳號隔離個別驗收。需取得全部必要證據後才能標 DONE。

## V1 技術與授權
1. Flutter Web/PWA → FastAPI `POST /integrations/google/gmail/radar/quick-scan` → Google Gmail API `gmail.readonly` → PostgreSQL。API **不接受其他人的 user_id / email**，使用 `current_user.sub` 授權。
2. 首版限定近期窗口（預設最近 7 天）和封數上限（最新 20 封（每輪三天補檢最多 40 封未查郵件）），使用 bounded Gmail `messages.list` 與 `messages.get(format=metadata)`。先用 deterministic 規則辨識明確通知與高價值候選；**未取得本人獨立 AI 同意時，不讀全文傳 Gemini**。未使用 Gemini 的狀態必須如實標「規則辨識」，不能標 AI 已分析。
3. 每人獨立資料與唯一約束 `(user_sub, gmail_message_id)`；相同郵件重掃不重建、不覆蓋已完成/忽略。必要資料：message ID、thread ID、分類、簡短說明、時間、狀態、最後掃描時間；不保存原信、附件、完整正文或 token。
4. 同使用者後端操作採有界互斥／資料庫 advisory lock 或 durable lease，不能只靠前端 disabled。快掃可以採有上限同步執行並返回實際結果；若工作超過 Cloud Run 請求可靠時間，應另採可靠 queue/Job 方案，不用無保證背景任務。
5. 在 Gmail 原信上有 Web/Android 連結；注意多帳號情境及 Gmail API messageId 不一定等同前端可直接定位的 thread route，若無法可靠直達則明確 fallback 至 Gmail 搜尋/收件匣；不假造保證。
6. 不建立 Cloud Scheduler、沒有 hourly/全員 worker、不啟用 background push，**本輪不以通知系統完整建成為 gate**。
7. API 權限失效、重連、Google 429/5xx、單封部分失敗，應顯示清楚；進行中不應寫成成功。紀錄不包含私人郵件正文。
8. Google `gmail.readonly` 是 restricted OAuth scope，對外產品 OAuth verification、安全評估仍為獨立風險，不能視為已核准。

## 驗收
- 使用者 A 快掃只讀寫 A，任何參數篡改無法處理 B；沒 Gmail scope 就返回明確重新授權狀態。
- 同人重複掃描只新增一次；完成／忽略狀態持久化；不同使用者可各自掃描。
- Flutter 在授權／成功零項／部分失敗／無權限／讀取失敗各狀態正確。
- 不啟用 Scheduler、Cron、通知 Worker 或私有全文 Gemini 處理。
- Backend tests、Flutter tests、Migration、4 類 CI、固定 Staging、正式發布與真實 Gmail 授權手機／Web 完整讀回：逐層 PASS／FAIL／NOT VERIFIED，不能僅憑程式提交標 DONE。
